## 任务目标

增强 `Publish.py` 的完整发布能力：运行脚本后不仅上传 PDF 到 Cloudflare R2、生成页面，还要自动提交并推送 `WebNote/PatTianFang.github.io` 子仓库，让 Cloudflare Pages 自动部署前端；同时清理项目中的确认生成垃圾，并处理 `Note/` 下 PDF 更新后的缓存问题。

## 思考过程

当前 R2 对象 key 使用稳定路径 `pdfs/<category>/<filename>`，适合覆盖上传。但如果 PDF 内容更新而 URL 不变，浏览器或边缘缓存可能继续使用旧 PDF。为兼顾稳定对象路径和更新可见性，采用 URL 查询参数版本号：页面链接使用 `?v=<源 PDF 修改时间戳>`，源 PDF 更新时 URL 自动变化。

自动提交/推送只应作用在 Cloudflare Pages 对应的静态站点子仓库 `WebNote/PatTianFang.github.io`，不应提交项目根目录的开发脚本和源笔记。清理只处理确认的生成产物：旧 `pdfs/` 发布副本、Wrangler 本地缓存、Python 缓存和 PyInstaller 输出。

## 遇到的问题

- 子仓库当前已有多项未提交生成文件，自动提交会把站点目录中的所有待提交内容一起提交，这是部署前端所需行为。
- 不能删除 `Note/` 源文件或已有文章内容；“多余文件”只能限定为明确生成产物。

## 解决方法

- 在 PDF URL 上追加基于源文件修改时间的 `v` 参数，解决同名覆盖后的缓存问题。
- 在 `Publish.py` 成功同步后，执行 `git add .`、`git commit`、`git push`。
- 清理 `WebNote/PatTianFang.github.io/pdfs/`、`.wrangler/`、`__pycache__/`、`build/`、`dist/`、`Publish.spec`。
- 更新根目录 `.gitignore`，避免 PyInstaller 输出再次进入待提交状态。
- 子仓库缺少 Git 提交身份导致首次自动提交失败后，在 `WebNote/PatTianFang.github.io` 内设置本地 `user.name=PatTianFang` 和 `user.email=pattianfang@outlook.com`，再提交并推送已生成的站点变更。
